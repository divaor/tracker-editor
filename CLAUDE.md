# Tracker Editor — notes for Claude

A Notepad++-style editor whose files sync through the same private GitHub data repo as Tracker (github.com/divaor/tracking_app). Electron on desktop, PWA on mobile.

## Commands

- `npm test` runs the unit tests (`node:test`, no browser needed). Run it before committing.
- `npm run web` serves `app/` at http://localhost:8080.
- `npm start` launches the Electron app. As root/in containers: `npx electron --no-sandbox .`
- `npm run vendor` re-bundles CodeMirror (from `vendor-src/codemirror.js`, esbuild with code splitting) into `app/vendor/cm/` and xterm.js with its fit add-on (`vendor-src/xterm.js`) into `app/vendor/xterm/`, `@codemirror/lsp-client` (`vendor-src/lsp.js`, pinned) as a second entry of the CodeMirror build (`cm/lsp.js`, its `marked` import pointed at `../marked.js`; the script fails if a chunk imports it), `@anthropic-ai/sdk` (`vendor-src/anthropic.js`, pinned) into `app/vendor/anthropic.js`, and copies Preact/htm, marked, DOMPurify and tesseract.js (with its core and the eng/spa models, into `app/vendor/ocr/`). Run it after upgrading any of them, and commit the output.

## Architecture

- `app/` is a no-build ES-module web app. GitHub Pages serves it directly and Electron loads it via the `app://editor` protocol (`electron/main.cjs`). Root `package.json` is `"type": "module"`, so Electron files are `.cjs`.
- Pure modules (no DOM, imported by the Node tests): `model.js`, `sync.js`, `github.js`, `search.js`, `ai.js`, `llm.js`, `asyncLlm.js`, `tracker-model.js`, `format.js`, `versions.js`, `crypto.js`, `naming.js`, `typing.js`, `previews.js`, `speech.js`, `selectionAsk.js`, `snippets.js`, `outline.js`, `logtools.js`, `checklist.js`, `capture.js`, `ocr.js`, `dictation.js`, `folders.js`, `where.js`, `codeNav.js`, `tabGroups.js`, `transfers.js` (its wording), `problems.js`, `indent.js`, `gitStatus.js`, `replace.js`, `emmet.js`, `completion.js`, `fileRefs.js`, `runFile.js`, `claude.js`, `providers.js`, `errorHelp.js`, `lspTools.js`, `localRepo.js`, `moveData.js`. The `.cjs` helpers `electron/diskFiles.cjs`, `clipHistory.cjs`, `folders.cjs`, `remote.cjs`, `sshConfig.cjs`, `findInFolder.cjs`, `mirror.cjs`, `zip.cjs`, `codeIndex.cjs`, `git.cjs`, `localShell.cjs` and `lsp.cjs` (with `test/helpers/fake-lsp.cjs`, a small server over stdio) are tested too. `searchPanel.js`, `htmlTools.js` and `columnSelect.js` import the CodeMirror bundle (it loads in Node too) and are tested; `formatter.js` and `commands.js` are pure too, and `electron/shellIntegration.cjs` is tested.
- Data repo layout:
  - `editor/index.json` lists file records; the text of each is in `editor/files/<id>/<safeName(name)>`.
  - `tracker.json` belongs to the tracker. The editor reads its projects and items, and writes it only for queued tracker ops (new projects, "Send to tracker") and for the sha of a tracker attachment edited here.
- `tracker-model.js` is a verbatim copy of the tracker's `app/js/model.js`. Refresh it when the tracker changes `tracker.json`'s format; never edit it here.
- Sync (`sync.js`) is one Git Data API commit per round:
  - File metadata merges last-write-wins on `updatedAt`. Text is tracked by blob `sha` (computed locally with `gitBlobSha`) against the `baseSha` the device last saw.
  - When both sides changed the text, ours stays and theirs is kept as a copy (`conflictName`). An edit to a file deleted elsewhere comes back as a new file.
  - A non-fast-forward branch update retries the round.
  - Deletions are tombstones, pruned after 180 days. Sync must never overwrite an index or `tracker.json` it cannot parse.
  - `encode`/`decode` hooks get the merged record: `syncManager` passes `vault.js`'s `encodeFor`/`decodeFor`, so encrypted files are stored as ciphertext. Copies made for conflicts keep `encrypted`.
- `store.js` keeps files, texts and the tab session in IndexedDB (`kv.js`) with debounced writes. `applySynced` must keep edits made while a sync was running.
  - Session: `open`, `active`, `closed`, `pinned` (always first in `open`), `side` (the split view's second pane, never `active`) and `collapsed` (folded project groups). `tidySession` keeps those rules.
  - Trash: a deleted file's text is kept in kv as `trash:<id>` (ids in `trashIds`) until its tombstone is pruned; `store.trash()` lists what can come back, the rest is fetched by blob sha.
  - Sealed texts: an encrypted file this device cannot read keeps only its ciphertext (`sealed`, kv `text:<id>` starting with the mark). `store.text()` is '' for it and it cannot be edited.
- Tracker documents: `store.docs()` lists the tracker's attached files from the last sync (`trackerDocs` in `model.js`).
  - Their texts are cached by blob sha (`docTexts`). `syncManager.downloadDocs` fetches missing ones after each sync.
  - Search, quick open and the model index address them as `r:<path>`; `actions.openFile` opens either kind.
- Previews: `previews.js` (pure) decides the kind (`previewKind`) and parses CSV and JSON errors; `ui/preview.js` renders them. HTML goes in a `sandbox=""` srcdoc frame (scripts off; the CSP is inherited anyway).
- Read aloud:
  - `speech.js` (pure) splits text into passages ({ from, to, text, kind, pause }), rewrites it for speech (`naturalize`: dates, abbreviations, asides; word lists for en/es/pt) and ranks voices.
  - `reader.js` speaks one passage at a time with one of two engines:
    - `device`: `speechSynthesis`. Pause cancels and restarts the passage, which works on Android too; a wake lock keeps the screen on.
    - `server`: an OpenAI-compatible `/audio/speech` endpoint. It plays audio, fetches the next passages ahead, sets Media Session metadata and handlers, and uses `localFetch` (the main process on desktop).
  - Highlighting goes through `editor.highlightReading`.
- Sharing to the app: the manifest's `share_target` posts to `share-target`. `sw.js` keeps the items in the `editor-inbox` cache, and `inbox.js` hands them to the app. `file_handlers` with `launchQueue` covers desktop Chrome and Edge.
- Saving:
  - Typing is saved 250 ms after the last key (editor debounce plus store debounce).
  - Pastes, drops and new tabs are saved at once: the editor passes `{ urgent }` and the store saves with ms 0.
  - `kv.js` writes with `durability: 'strict'` and `tx.commit()`.
  - `main.js` flushes pending saves on `pagehide` and when the app is hidden.
  - The Electron crash test kills the app 150 ms after a paste; keep it passing.
- `naming.js` (pure) names untitled tabs (`new N`) from their content: the model's reply via `cleanModelName`, or `nameFromHeading`. With the model it also files new notes: `filingMessages` asks for JSON `{ name, project, tags }`, `parseFiling` keeps only existing projects (their spelling) and at most 3 tags. `app.js` runs it a moment after text changes, once per new file, filling only empty fields, with Undo.
- History and compare: `versions.js` lists a file's versions from the commits API (`path` = the file's folder, which follows renames) and loads one. `editor.createCompareView` is `@codemirror/merge` (side by side, unified on phones); `ui/compare.js` takes the editor's place, `ui/history.js` is the panel.
- Encryption: `crypto.js` (pure, WebCrypto): PBKDF2-SHA256 → AES-GCM; sealed text is `TRACKER-EDITOR-ENCRYPTED v1` then base64(iv + ciphertext). The tracker's connector checks that first line, so keep it. `vault.js`: `editor/vault.json`, the non-extractable key in kv, and a per-file cache so unchanged text keeps its ciphertext (and blob sha).
- Typing into another window (desktop): `typing.js` prepares the text, `electron/typer.cjs` presses the keys (Windows: PowerShell + C# SendInput with scan codes, never into this window, stops on a focus change or Escape; macOS: osascript; Linux: xdotool with a UTF-8 locale, or wtype). IPC `type:start` / `type:stop` / `type:progress`. With `lineStart` (the setting "the other editor indents new lines by itself"), after each Enter it selects to the line start (Shift+Home), types a space and Backspace, so the target's auto-indent is cleared and the line's own indentation is typed (Windows: Home needs `KEYEVENTF_EXTENDEDKEY`; macOS: Cmd+Shift+Left; Linux: `lineRuns`, one xdotool run per line since `type` takes the rest of its arguments).
- `ui/share.js`: Web Share (as text or file) where available, otherwise and also email/WhatsApp links (long text goes to the clipboard), Teams (copy and open), copy text/link, save.
- Effects that must win races with fast input are layout effects: creating and switching the editor tab, Escape handlers in Modal and QuickOpen, and the keys of the folders view's viewer.
- `tabLock.js`: only one browser tab runs the app (Web Locks + BroadcastChannel). A new tab takes over, and the old one flushes, stops syncing and shows "Use it here".
- `editor.js`: one CodeMirror `EditorView`, with an `EditorState` per tab, plus a second view for the split view's side pane (`openSide`/`closeSide`). A tab's state lives in one view at a time and moves with its undo history; commands and reading aloud use the pane typed in last. Languages load lazily from `@codemirror/language-data`.
- Code tools (`editor.js` + `codeNav.js`, pure):
  - Folding: the fold gutter always shows; languages without their own folding (plain text, `StreamLanguage` modes) get `indentFolding`. `foldLevel(n)` unfolds, then folds the blocks at depth n (`foldableBlocks`; 0 = all of them, nested included). Keys Alt+0 / Alt+Shift+0 / Alt+1–3 (layout-safe: CodeMirror falls back to the key code).
  - `languageName` (a facet set with the language in the `lang` compartment) gives `outlineOf(state)` (outline.js, cached per doc and language) and `scopeAt` (the symbols whose fold contains the cursor, "Store › save") for the status bar (`cursor.scope`).
  - F12 / Shift+F12 / F2 go through `onShortcut` to `actions.goToDefinition` / `findUsages` (`ui/usages.js`, `panel === 'usages'`) / `renameSymbol` (`selectOccurrences`: every whole-word use selected). `codeNav.js`: `wordAt`, `occurrences`, `declarationKind` (regex heuristics: 'strong' declarations, or 'assign' at a line start), `findDefinition` (nearest strong one before the cursor, else the first after; assignments only without others).
  - Quick open with `@` lists the file's outline (`matchSymbols`) and `actions.revealSymbol` selects the name. `highlightSelectionMatches` also marks the word under the cursor.
- Column selection from the keys (`columnSelect.js`): `columnKeymap` comes before `defaultKeymap` (Shift+Alt+arrows as in Notepad++, so not CodeMirror's copy line up/down; Ctrl+Shift+Alt+arrows; Cmd+Shift+Option on macOS; Ctrl+Alt+↑/↓ `addCursorAbove`/`Below`). The `columnBox` field keeps the box in columns ({ anchor, head }: { line, col }, tabs to their stop) until the text or selection changes otherwise; without one, `boxOf` makes it from the selection (several ranges: their first and last lines, grown the way the key points). Short lines get a cursor at their end, as with `rectangularSelection`.
- The menu bar (Windows, Linux: `autoHideMenuBar`) shows only for a plain Alt: `before-input-event` swallows the Alt keyUp after another key with Alt, and the preload reports `mousedown`/`wheel` with Alt (`menu:alt-used`, Alt+drag), since Electron toggles it on any Alt release that no key came between.
- Problems as you type (`problems.js`, pure; `editor.js` `problemsLinter`, @codemirror/lint): JSON by `jsonProblem` (previews.js; comments and trailing commas blanked for `isJsonc` names), YAML by `yamlProblems` (a key twice in a mapping, tabs, an open quote) plus the parser, and for `SYNTAX_LANGUAGES` the parser's error nodes (`treeErrors`: also mismatched/missing close tags) worded by `syntaxProblems` (HTML, Vue, PHP: warnings). SQL and Markdown are not checked (their parsers accept anything or flag valid code). The linter reports each result to the app (`onProblems`: status bar `.status-problems`, `ui/problems.js` `ProblemsPanel`, `panel === 'problems'`, Ctrl+Shift+M in the window's key handler); F8 / Shift+F8 are `nextDiagnostic` / `previousDiagnostic`. Setting `problems`.
- Indentation per tab (`indent.js`, pure: `detectIndent`, `convertIndent`, `editorConfigIndent`): the host keeps `indents` (key → { tabs, size, source }), set when a state is made (`settleIndent`: settings `indentChosen[key]`, else detected when `detectIndent`), by `disk:editorconfig` for disk tabs (the main process reads the `.editorconfig` files above the file, up to `root = true`, and returns only the indentation), or picked in the status bar (`IndentButton`; `actions.setIndent` / `convertIndent`, remembered in `indentChosen`, 300 at most). `tabSize` is for files that do not say.
- Reading aids (`editor.js`, compartment `aids`, settings `indentGuides`, `bracketColors`, `stickyScroll`): guides are a line decoration with a CSS gradient (`--guides`, `--unit`); bracket colors come from the tree's bracket tokens (plain text counts characters), depths cached per tree; sticky scroll is a `.cm-sticky` overlay in the editor (`scopeEntries`: the outline entries around the top line) placed in a measure cycle.
- Quick open over folders (desktop): `folderIndex.js` asks `folder:index` (`listFiles` in findInFolder.cjs: breadth-first, no links, `SKIP_DIRS`, limits; on servers only while connected) for each folder shown in Folders (`folderRoots` in app.js), keeps the lists 30 s (forgotten on `folder:changed`) and gives `QuickOpen` entries with `rel` (the path inside the folder, also matched by `quickOpen`); text files only (`opensInEditor`), opened with `actions.openDiskPath`.
- Across files (desktop for the folders): `actions.declarationElsewhere` (F12 when `findDefinition` finds nothing in the file) looks in the synced files (`occurrences` + `declarationKind` 'strong') and asks `code:declarations` (`codeIndex.cjs` `findDeclarations`: breadth-first over the folders shown, code files by `languageForName` in outline.js, a time limit); one place opens (`actions.openAt`), several go to `DeclarationPicker` (`ui/symbols.js`, dialog `declarations`). Ctrl+T (`SymbolSearch`, dialog `symbols`; `#` in quick open) ranks the synced files' outlines and `code:symbols` (`createSymbolIndex`: outlines per file, read again when the mtime changes, refreshed when asked after 20 s).
- Git (desktop, folders on this computer, read-only): `electron/git.cjs` runs the installed `git` (`GIT_OPTIONAL_LOCKS=0`; none installed: null, asked once): `git:status` (porcelain v2, `gitStatus.js` `parseStatus`) for the folders shown, and `git:head` (the file at HEAD, its branch). Page: `gitState.js` keeps the status per folder (read again with each `load`), `gitCodeOf` / `statusOf` give rows their code (`.git-badge`, `folder-row.git-*`) and headers their `.git-branch`. Disk tabs get the HEAD text through `host.setGitBase` (`gitGutter.js`: a gutter in the `gitBar` compartment, `lineChanges` Myers diff per edit, up to 2 MB); the status bar's `.status-git` shows the branch and changed lines; `actions.compareWithHead` opens the comparison (also on window focus the HEAD text is read again).
- Replace in a folder: `ui/folderSearch.js` shows a Replace line (preview with `<del>`/`<ins>` per match via `replace.js`), ticks per file, and calls `folder:replace` (main: each file read, `replaceAll`, written back with its format only if unchanged since read; the old texts kept for `folder:replace-undo`, which writes back only over what it wrote). Files with unsaved edits in a tab are left out; open tabs reload.
- Tab views (`tabGroups.js`, pure; `tabViews.js` feeds it from the store and settings): every open tab has a group (`groupOf`): `assigned` by hand, else a disk/server tab's folder (the deepest of `groupContext().folders`: the picked folder behind each Folders section (`sectionFolders`, `folder:roots`; a server's top folder), `session.groupFolders` kept while their tabs are open (`rememberFolders`), and folders linked in `folderProjects`), as `p:<project key>` when the folder is linked, else `f:<path>`; synced files and tracker documents by project, else `notes`; the rest `other`. `session.view` (group ids, null = all; `pinned` too) picks what the bar shows (`viewTabs`: plus pinned tabs with `pinnedEverywhere`, and the open/side tab from elsewhere as `guests`); `viewActive` remembers each view's last tab (`viewKey`), `store.setTabView` / `assignGroup`. Colors: projects' own, folders `folderColors` or `folderColor` (`FOLDER_COLORS`, never a kind color, not one another group shows); `tabColors` 'auto' draws `--gc` under tabs when two colored groups show; Folders headers use `folderGroupOf` (the same color). UI: the switcher (`ui/tabViews.js` `TabViewMenu`, `tabs:views` / `tabs:move` events, Alt+V, Ctrl+Alt+PageUp/PageDown/Home in the window's key handler), `FolderGroupDialog` (link to a project, color; a folder named like a project is offered once, recorded as '' in `folderProjects`), `.status-group`. `cycleTab`, closing and Close others/all work on the bar's tabs; `newFile` files into the one group shown; Ctrl+P lists open disk tabs (`openTabs`).
- The tab bar (`TabBar` in `ui/tabs.js`): `.tabbar` scrolls sideways without a scrollbar inside `.tabbar-wrap`; a non-passive wheel listener turns vertical wheel turns into sideways scrolling; `hiddenTabs` counts the tabs past each edge for the `.tab-hint` buttons (measured after each render, on scroll and on resize; `scroll-padding-inline` keeps the open tab clear of them). Double-click pins or unpins, middle-click closes (its mousedown is cancelled so Windows does not start autoscroll). Touch screens (`pointer: coarse`): tabs are not draggable, the open tab has ⋯ (`.tab-menu`) and a long press (`LONG_PRESS_MS`, pointer events; the click after it is swallowed) opens the tab menu. `hiddenTabs` also says past which edge the open tab is (`activeSide`): that hint reads "open tab" and a click brings it back (`reveal`); `.tab-list-btn` (▾, shown when the tabs overflow) lists them all. Commands `reveal-tab` / `tab-list` reach the bar through the `tabs:reveal` / `tabs:list` window events.
- `ui/menu.js`: `Menu` (fixed position, so bars that scroll sideways do not clip it) and `MenuButton`; the file bar's More menu and the tab context menu use them. Items may carry a `hint` (shown muted, and as the title) and a `key`.
- Find and replace: `searchPanel.js` is CodeMirror's search panel drawn our way (`search({ createPanel })`, class `find-bar`, not `cm-search`, so the package's base theme does not apply). The field is `[main-field]` (`openSearchPanel` focuses it); toggles are `aria-pressed` buttons; `countMatches` counts up to `COUNT_CAP` a moment after changes. `openReplacePanel` (Ctrl+H; Cmd+Alt+F on macOS) shows the replace line, which stays open from one search to the next; Replace replaces the next match in one click. No Alt shortcuts in the bar: Alt+W and Alt+R belong to the app.
- Sizes dragged by hand (`ui/splitter.js` `Splitter`: pointer drag, arrow keys, double-click resets; `body.resizing-x/-y` keeps iframes from swallowing the pointer): settings `sidebarWidth` (the `.app`'s `--sidebar`, 0 = default), `splitRatio` (`.editor-area`'s `--split`, the editor's share next to a preview or the side view), `terminalHeight`, `folderPreviewHeight`. While dragging, the CSS variable is set on the element; the setting is saved when it is let go.
- The preview pane has a header (`.preview-head`): Full view (`previewFull` in app.js: `.editor-area.preview-full` hides the editor), Full screen (`requestFullscreen` on the pane), close. `PreviewBody` is the reading view alone (the folders view uses it read-only: without `onToggle`, Markdown boxes do not change).
- Format document (`actions.formatDocument`, Shift+Alt+F): `formatter.js` picks by language, then name (`formatterFor`), or guesses JSON/XML. JSON (`formatJson`, token by token: numbers never go through JSON.parse; comments kept) and XML (`formatXml`) are formatted there; SQL by sql-formatter and the rest by Prettier, vendored in `vendor/format/` as `.js` (`npm run vendor`; `.mjs` is not served as JavaScript everywhere) and loaded when first used. The selection only, when there is one. Editing commands (upper case, sort lines…) stay in editor.js `COMMANDS`.
- HTML, XML and JSX (`htmlTools.js`; settings `emmet`, `linkedTags`): Tab runs `emmetOnTab` before `indentWithTab` (MARKUP languages only, not in a tag, string or comment; JSX has its own rule), which expands with `emmet.js` (pure: `abbreviationBefore`, `expandAbbreviation`: `> + ^ * $ () # . [] {}` and `!`, indented with the `indentUnit`, the cursor in the first empty spot; JSX gets `className`/`htmlFor`). Closing tags as you type is lang-html/lang-xml's own `autoCloseTags`. `linkedTags` is a transaction filter: a typed edit inside one end's tag name, when both names matched before, gets the same edit at the other end (one undo step).
- Terminal on this computer (desktop): `term:open` with `'local'` uses `electron/localShell.cjs` (`@lydell/node-pty`, prebuilt per platform, pinned; `build.asarUnpack` keeps it out of the asar, its `.pdb` files are left out): `defaultShell` (pwsh, else Windows PowerShell; `$SHELL`, login on macOS), `shellEnv` (without Electron's and an AppImage's variables), `startDir` (an existing absolute folder, else home: no pick needed, a shell reaches everything anyway), the same face as `remote.openShell` (`data`/`exit`/`close`, `write`, `setWindow`, `close`). The page cannot name the program or its arguments; keep it so. `term:open` returns `{ id, shell }`. Page: `terminals.js` sessions with `connId === 'local'` (`kind-disk` tabs), `actions.localTerminalDir`, `toggleTerminal` opens one here when no server file or folder is in front; `terminalHere` opens the panel's, `systemTerminalHere` the system's (`folder:terminal`).
- Run this file (desktop, F5 in the window's key handler, command `run-file`): `actions.runFile` flushes and saves a disk tab, then `runFile.js` (pure: `runCommandFor` by extension, `RUN_COMMANDS` + setting `runCommands` parsed by `parseRunCommands`; `quoteFor` per shell; `runLine` cd's into the folder first) and `terminals.js` `runInTerminal` (one `runner` session per place, reused). Servers: their SSH terminal, posix. `.html` opens in the browser.
- Language servers (desktop, setting `languageServers`; disk tabs on this computer):
  - `electron/lsp.cjs`: `CATALOG` (TypeScript: the project's TypeScript ≥ 7 `tsc --lsp`, else typescript-language-server, else a global TypeScript ≥ 7; Python: pyright-langserver / basedpyright-langserver), found in the project's `node_modules` or on PATH (plus the login shell's, `shellPath`); Node scripts (npm links, `.cmd` shims) run on Electron's own Node (`ELECTRON_RUN_AS_NODE`). `findRoot` (markers, never above the picked folder), `frame` / `createReader` (Content-Length), `createLspHost`: one server per (catalog entry, root, page), four at most (the one used longest ago stops), restarted after a crash with back-off and left `stopped` after three in 5 minutes; each start bumps `generation`. The page names a file, never a program; keep it so. IPC `lsp:start` (checkFile; `{ none }`, `{ missing: { install } }` or the server's info with `languageId`, `init`, `settings`), `lsp:send`, `lsp:message`, `lsp:status`, `lsp:stop`, `lsp:restart`, `lsp:list`; a page reload stops its servers.
  - `app/js/lsp.js`: one `LSPClient` (`vendor/cm/lsp.js`) per server, our `TabWorkspace` (a file stays open on the server while its tab is open, shown or not; `syncFiles` uses the plugin's changes or the whole text; `connected` re-sends the files as they are now after a restart), server requests answered (`workspace/configuration` from the catalog's `settings`: TypeScript's `useAliasesForRenames: false`), push (`publishDiagnostics`) and pull (`textDocument/diagnostic` after each sync, `autoSync`) problems into the editor's linter through the `serverProblems` facet (`host.refreshProblems` dispatches `problemsChanged`, since `forceLinting` alone only hurries a run already due), `$/progress`, Escape hiding signature help (`cm-signature-hidden`). The host's `server` compartment holds the client's plugin, completion, hover and signature help (`host.setLanguageServer`); `onDrop` forgets a tab's file.
  - `app.js`: F12 / Shift+F12 / F2 ask the server first (`actions.serverPlaces`, `ReferencesPanel`, `RenameSymbolDialog` → `actions.renameWithServer`: open tabs through `host.applyChanges`, files not open read and opened as unsaved tabs, 30 at most) and fall back to `ownWays` (codeNav.js). `ui/languageServers.js`: the panel (`panel === 'servers'`), `SetupServerDialog` (`actions.typeInTerminal`: `runInTerminal` with `enter: false`); the status bar's `ServerStatus` (ui/tabs.js).
- `file:line` links (`fileRefs.js`, pure: `findFileRefs` for Node/compilers/Python/.NET/TypeScript forms, `resolveRef`): xterm's `registerLinkProvider` in `terminals.js` (`setRefHandler`; base = the session's folder, a `remote://` one on servers) and Ctrl+click in the editor (`onOpenRef`, base = a disk tab's folder) go to `actions.openRef` → `openDiskPath` (the main process still checks the path is allowed).
- Suggestions as you type (setting `inlineSuggest`, off by default; `llm.completeModel`, '' = the chat model): `inlineSuggest.js` (a ghost widget field; `Prec.highest` Tab / Mod-ArrowRight / Escape; asks `WAIT_MS` after typing, only where `shouldSuggest`; `cover` = the closing brackets after the cursor the suggestion writes too (`restCovered`), hidden while shown and replaced on accept). `actions.suggestText` asks `llm.complete` (`/completions` with `suffix`: fill in the middle) and, when a server answers 400/404/405/422/501, remembers that (`fillsMiddle`) and asks the chat with `completionMessages`; `cleanCompletion` trims the answer. Never for encrypted files or async services.
- The command palette (`ui/palette.js` `CommandPalette`, dialog `palette`; Ctrl+Shift+P in the window's key handler, `>` in quick open): `findCommands` rows without `run: false`, run with `actions.command`. Macros play with Alt+Shift+P (`e.code === 'KeyP'`, layout-safe); the editor's recorder skips both macro keys.
- Help (F1, `ui/help.js`): `commands.js` lists every command with its keys (`Mod` = Ctrl or Cmd; `desktop` keys, `only: 'desktop'`, `run: false` for keys that work only in place); `actions.command(id)` runs one (the desktop menu goes through it too); test/commands.test.js checks each runnable id is handled. While searching, `findCommands` puts label matches first and `groupsOf` orders the groups by their best match, so Enter runs the top row. The guide is `app/help/guide.md` (the same text goes to the tracker as a doc): keep it current when features change.
- `components.js` `ClearButton`: the × in search and filter fields, shown while they have text; it empties them and focuses the input next to it.
- The model panel (`ui/askSelection.js`: `AssistPanel`, opened by `AssistBubble` or Ctrl+K; setting `assistBubble`): `selectionAsk.js` lists the actions by group; kind `answer` replies in the panel (follow-ups resend the earlier turns), kind `replace` opens `actions.proposeReplacement` (compare, Accept / As a new file / Copy). `param` actions ask for a value that fills `{param}` (`withParam`). The context is the selection of the pane typed in last, or the whole file (`actions.assistContext`). `actions.openAssist({ action, context })` opens it asking one action at once (`assistStart`; a context may carry `label`, `errorText` and `fixTarget`). ## When changing things

- Adding or removing a file under `app/` → update `ASSETS` in `app/sw.js` (CodeMirror chunks are listed in `vendor/cm/files.json` instead, and text recognition in `vendor/ocr/files.json` and the terminal in `vendor/xterm/files.json`, both cached when first used). `test/app.test.js` enforces this.
- Bumping the version → update `package.json`, `app/js/version.js` and the `CACHE` name in `app/sw.js`. The tests check that they match.
- The manifest `id` is `/tracker-editor/`. Ids resolve against the origin, and the tracker on the same origin (divaor.github.io) owns the origin root. Never change it: a new id makes installed copies a different app.
- The CSP in `app/index.html` allows only same-origin scripts. Fetches may go to any https origin and to `localhost` (the model and speech servers); `media-src` allows `blob:` for speech audio, `img-src` and `frame-src` allow `blob:` for the folders view's pictures and PDFs.
  - Do not add inline scripts.
- Browser tests (Playwright) need `PLAYWRIGHT_DISABLE_FORCED_CHROMIUM_PROXIED_LOOPBACK=1` in this sandbox so `localhost` is not sent through the proxy. Electron tests need `xvfb-run`; typing into another window needs `xdotool` (`apt-get install xdotool`).
  - Server tests use OpenSSH's `sshd` (with `UsePAM yes` and `KbdInteractiveAuthentication yes` for the server's own password question), ssh2's `Server` for two-step sign-in (with `/usr/lib/openssh/sftp-server` behind its sftp subsystem; do not add an `sftp` listener), and pyftpdlib for FTP/FTPS.
  - Playwright's key presses do not reach Electron menu accelerators: click the menu item through `Menu.getApplicationMenu()` instead.
  - Without a keyring, `safeStorage` is unavailable under xvfb, so the clipboard history stays in memory there.

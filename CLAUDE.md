# Tracker Editor — notes for Claude

A Notepad++-style editor whose files sync through the same private GitHub data repo as Tracker (github.com/divaor/tracking_app). Electron on desktop, a Capacitor app on Android, PWA elsewhere.

## Commands

- `npm test` runs the unit tests (`node:test`, no browser needed). Run it before committing.
- `npm run web` serves `app/` at http://localhost:8080.
- `npm start` launches the Electron app. As root/in containers: `npx electron --no-sandbox .`
- `npm run android:node` (`scripts/android-node.js`) fetches nodejs-mobile's libnode (pinned, `npm pack`) into `android/app/libnode/` and assembles the Node side into `android/app/src/main/assets/nodejs/` (`--assets-only` skips libnode); neither is committed. Then `npx cap sync android` and `./gradlew assembleDebug` in `android/` (needs the Android SDK and NDK: CI does it, `.github/workflows/android.yml`; releases sign with the `ANDROID_KEYSTORE` / `ANDROID_KEYSTORE_PASSWORD` secrets and skip the APK without them).
- Actions → **Android check** (`.github/workflows/android-check.yml`, by hand) builds a debug APK with WebView debugging on (that build only), runs it in an emulator (x86_64, the arm64 libraries translated) and `scripts/android-check.mjs` drives its real WebView through Playwright's `_android` (`playwright-core`, installed there with `--no-save`): text from an image, a PDF with pdf.js's own worker, converted documents, the phone's text to speech (spoken, and made ahead and read through; passes when the emulator has no engine), and Kokoro-FastAPI run on the CI machine (a pinned `kokoro-fastapi-cpu` container, `KOKORO` = `http://10.0.2.2:8880/v1`, the host as the emulator reaches it) read from the app through its Node.js, a shell on the phone (the bridge's `term:open` in the phone's Download folder, with all files access given by `appops`, then `` Ctrl+` `` and typing into the panel), and turning sideways (rotation locked upright: the plugin's `sideways`, then a folder comparison of two folders in Download, picked in the app's own chooser by `tapText`, a uiautomator dump and `input tap`: one tree, Sideways, two columns, Upright, a copy, two panes). Its artifact holds `report.json`, a screenshot, the WebView's console lines and Node's (`TrackerNode`). Run it after changing workers, wasm or anything the WebView loads by itself.
- `npm run vendor` copies pdf.js (pinned `pdfjs-dist`, its legacy build as `.js`, with the wasm decoders but not the scripting sandbox, cmaps, standard fonts and ICC profile) into `app/vendor/pdf/`, re-bundles CodeMirror (from `vendor-src/codemirror.js`, esbuild with code splitting) into `app/vendor/cm/` and xterm.js with its fit add-on (`vendor-src/xterm.js`) into `app/vendor/xterm/`, `@codemirror/lsp-client` (`vendor-src/lsp.js`, pinned) as a second entry of the CodeMirror build (`cm/lsp.js`, its `marked` import pointed at `../marked.js`; the script fails if a chunk imports it), `@anthropic-ai/sdk` (`vendor-src/anthropic.js`, pinned) into `app/vendor/anthropic.js`, and copies Preact/htm, marked, DOMPurify and tesseract.js (with its core and the eng/spa models, into `app/vendor/ocr/`). Run it after upgrading any of them, and commit the output.

## Architecture

- `app/` is a no-build ES-module web app. GitHub Pages serves it directly and Electron loads it via the `app://editor` protocol (`electron/main.cjs`). Root `package.json` is `"type": "module"`, so Electron files are `.cjs`.
- Pure modules (no DOM, imported by the Node tests): `docBookmarks.js`, `docSpeech.js`, `model.js`, `sync.js`, `github.js`, `search.js`, `ai.js`, `llm.js`, `asyncLlm.js`, `tracker-model.js`, `format.js`, `versions.js`, `crypto.js`, `naming.js`, `typing.js`, `previews.js`, `speech.js`, `selectionAsk.js`, `snippets.js`, `outline.js`, `logtools.js`, `checklist.js`, `capture.js`, `ocr.js`, `dictation.js`, `folders.js`, `where.js`, `codeNav.js`, `tabGroups.js`, `transfers.js` (its wording), `gitAssist.js`, `fileSteps.js`, `testRun.js`, `problems.js`, `indent.js`, `gitStatus.js`, `replace.js`, `emmet.js`, `completion.js`, `fileRefs.js`, `runFile.js`, `claude.js`, `providers.js`, `errorHelp.js`, `editorHelp.js`, `lspTools.js`, `localRepo.js`, `moveData.js`, `fileTypes.js`, `comparePick.js`, `folderCompare.js`, `folderPick.js`, `panes.js`, `paneLayout.js`, `crumbs.js`, `minimapLayout.js`, `codeMenu.js`, `terminalTabs.js`, `textSize.js`, `editKeys.js`, `askFind.js`, `askSources.js`, `quickRows.js`, `debugTools.js`, `keybindings.js`. The `.cjs` helpers `electron/diskFiles.cjs`, `clipHistory.cjs`, `folders.cjs`, `remote.cjs`, `sshConfig.cjs`, `findInFolder.cjs`, `mirror.cjs`, `zip.cjs`, `codeIndex.cjs`, `git.cjs`, `localShell.cjs`, `folderCompare.cjs`, `testProject.cjs`, `lsp.cjs`, `lspRemote.cjs`, `askFolders.cjs` (with `test/helpers/fake-lsp.cjs`, a small server over stdio) and `dap.cjs` (with `test/helpers/fake-dap.cjs`, a debug adapter over stdio or as a server) are tested too. `searchPanel.js`, `htmlTools.js` and `columnSelect.js` import the CodeMirror bundle (it loads in Node too) and are tested; `formatter.js` and `commands.js` are pure too, and `electron/shellIntegration.cjs` is tested.
- Data repo layout:
  - `editor/index.json` lists file records; the text of each is in `editor/files/<id>/<safeName(name)>`.
  - `tracker.json` belongs to the tracker. The editor reads its projects and items, and writes it only for queued tracker ops (new projects, "Send to tracker") and for the sha of a tracker attachment edited here.
- `tracker-model.js` is a verbatim copy of the tracker's `app/js/model.js`. Refresh it when the tracker changes `tracker.json`'s format; never edit it here.
- Sync (`sync.js`) is one Git Data API commit per round:
  - File metadata merges last-write-wins on `updatedAt`. Text is tracked by blob `sha` (computed locally with `gitBlobSha`) against the `baseSha` the device last saw.
  - When both sides changed the text, ours stays and theirs is kept as a copy (`conflictName`). An edit to a file deleted elsewhere comes back as a new file.
  - A non-fast-forward branch update retries the round.
  - Deletions are tombstones, pruned after 180 days. Sync must never overwrite an index or `tracker.json` it cannot parse.
  - `encode`/`decode` hooks get the merged record: `syncManager` passes `vault.js`'s `encodeFor`/`decodeFor`, so encrypted files are stored as ciphertext. Copies made for conflicts keep `encrypted`.
- `store.js` keeps files, texts and the tab session in IndexedDB (`kv.js`) with debounced writes. `applySynced` must keep edits made while a sync was running.
  - Session: `open`, `active`, `closed`, `pinned` (always first in `open`), `panes` (the tabs of the panes beside the main one, in order: never `active`, each once, no comparisons, three at most: `tidyPanes`; an old session's `side` becomes the first, `migratePanes`) and `collapsed` (folded project groups). `tidySession` keeps those rules (with no active tab, the first pane's takes its place).
  - Trash: a deleted file's text is kept in kv as `trash:<id>` (ids in `trashIds`) until its tombstone is pruned; `store.trash()` lists what can come back, the rest is fetched by blob sha.
  - Sealed texts: an encrypted file this device cannot read keeps only its ciphertext (`sealed`, kv `text:<id>` starting with the mark). `store.text()` is '' for it and it cannot be edited.
- Tracker documents: `store.docs()` lists the tracker's attached text files from the last sync (`trackerDocs` in `model.js`; `isTextAttachment` from `tracker-model.js` leaves out pictures, PDFs and other files, never downloaded as text). A PDF or other document opened from the tracker's `#/repo/<path>` link (`documentKind`) is a repo tab with `doc` (its kind; `store.openRepoFile({ doc })`, `setRepoText` refuses it, so it is never written back) shown by `DocumentView` with `repoBytes(path)` (`getFileBytes` from the data client); other non-text files say to open them in the tracker. Saved repo tabs go through `settleRepoTab` on load (versions before 0.34 opened any attachment as text: a document's becomes a document tab, others close), and sync never writes text over a path that is not a text attachment.
  - Their texts are cached by blob sha (`docTexts`). `syncManager.downloadDocs` fetches missing ones after each sync.
  - Search, quick open and the model index address them as `r:<path>`; `actions.openFile` opens either kind.
- Previews: `previews.js` (pure) decides the kind (`previewKind`) and parses CSV and JSON errors; `ui/preview.js` renders them. HTML goes in a `sandbox=""` srcdoc frame (scripts off; the CSP is inherited anyway).
- Read aloud:
  - The tracker keeps copies of `speech.js`, `docSpeech.js`, `reader.js`, `ui/readAlong.js`, `ui/voicePicker.js` and `ui/readAloud.js` (and their tests): keep them in step. `reader.js` takes the app's name for the lock screen from index.html's `application-name`.
  - `speech.js` (pure) splits text into passages ({ from, to, text, kind, pause }), rewrites it for speech (`naturalize`: dates, abbreviations, asides; word lists for en/es/pt) and ranks voices.
  - `reader.js` speaks one passage at a time with one of two engines:
    - `device`: `speechSynthesis`, or in the Android app (whose WebView has none) the phone's TextToSpeech (`window.desktop.android.tts`: androidApp.js `speech()` → plugin `ttsVoices` / `ttsSpeak` / `ttsSynthesize` / `ttsStop` / `keepAwake`, `Speech.java`; the manifest's `<queries>` lists `TTS_SERVICE`, or Android 11+ hides the engine; voices as `{ voiceURI: name, name, lang, localService, quality }`, `onVoicesChanged`, an empty list asked for again (an engine just started may list none yet); a stop rejects what waits with code `interrupted`). In the app the passages are made into audio ahead (`synthesize`: `synthesizeToFile` into the cache, a base64 WAV back, the file removed; `AHEAD.device`) and played by the page's `Audio` like a server's (`playsAudio`), so an engine slower than speech (Kokoro on the phone) leaves no silence before each sentence; an engine that cannot make files speaks each passage itself (`direct`). The engine is the app's choice: setting `tts.androidEngine` (a package, '' = the phone's preferred one; `setVoiceEngine`, passed as `engine` on each call, `Speech.useEngine`, an uninstalled one falls back), `ttsVoices` lists `engines` (`voiceEngines()`). Pause cancels and restarts a spoken passage (audio pauses mid-sentence); a wake lock (in the app `FLAG_KEEP_SCREEN_ON`) keeps the screen on.
    - `server`: an OpenAI-compatible `/audio/speech` endpoint. It plays audio, fetches the next passages ahead, sets Media Session metadata and handlers, and uses `localFetch` (the main process on desktop, the app's Node.js on Android, so plain http on the network works there). Its API key is the secret `TTS_KEY_SECRET` (`tts-server-key`, in `SECRET_KEYS` too), sent only to `tts.server.keyOrigin` (`originOf` the address it was saved for); an old `tts.server.apiKey` moves there on load.
  - Choosing a voice: `ui/voicePicker.js` `VoicePicker` (the read-aloud bar and Settings; a dropdown, a sheet on phones; never a `<select>`, whose popup a phone draws itself): each voice as `describeVoice` (speech.js, pure: Kokoro's names and keys through `kokoroVoice` with accent and gender, Piper's model names, Google's `xx-yy-x-code-local|network`, browsers' "Name - Language"; `languageName` by Intl.DisplayNames), the text's language first, the rest folded away unless searched, Android's engines as chips, ▶ (`onSample`, Settings only: `startReading({ voice })`, a voice for that reading).
  - Highlighting goes through `editor.highlightReading`, unless the reading was started with `onPassage` (pages read as shown: their own highlighter). `startReading`'s `kindOf(passage)` makes whole paragraphs headings, items, rows or code (their pauses).
  - Pages read as shown (`ui/readAlong.js`; `docSpeech.js`, pure: `readsAloud` (not spreadsheets), `tidyBlock` (with the map back to the raw text), `joinBlocks`, `blockAt`, `passageInBlock`, `firstBelow`, `pdfSpeechText`): `readingBlocks` (text grouped by `READ_BLOCKS`, each text node's place kept; `notRead`, `skip` for code, announced by `codeSkippedWords`), `selectedBlocks`, `pageSource(root, scroller)` (from the selection, else the top of the screen), `readAlong(source)` → startReading's `text`, `from`, `to`, `kindOf`, `onPassage`: the block gets `doc-reading`, the sentence the CSS Custom Highlight `reading` (`::highlight(reading)`; the page is not changed), and `keepInView` follows them. Documents: `DocumentView` with a `readKey` gives `listen()` (app.js keeps it in the module's `docReader`, so Alt+R and the bar's Listen reach it; the folders viewer passes `listenInBar`); its `nav.reading()` gives the source (converted: `pageSource`; PDF: its pages through `pdfPageTexts`, the page marked and turned to). The Markdown preview: `Preview`'s Listen (`.preview-listen`, `readKey` `preview:<tab key>`) reads the rendered page; `onReader` registers `previewReader`, which Alt+R uses while the preview hides the text (`textHidden`: Full view, phones; full screen). Reading stops when its view goes.
- Sharing to the app: the manifest's `share_target` posts to `share-target`. `sw.js` keeps the items in the `editor-inbox` cache, and `inbox.js` hands them to the app. `file_handlers` with `launchQueue` covers desktop Chrome and Edge.
- Documents shown as they look, read-only (PDF, EPUB, FictionBook, Word, OpenDocument text/sheets/slides, RTF, Excel, PowerPoint): `docTypes.js` (pure: `DOCUMENT_TYPES` by extension, `documentKind(name, mime)`; `electron/diskFiles.cjs` `DOCUMENT_EXTS` is its copy, test/documents.test.js keeps them equal).
  - Tabs: `disk:read` (diskFiles.cjs `readTextFile`, remote.cjs `read`, androidApp.js `readFile` for content://) gives a document `{ doc: kind, text: '' }` without reading it; the store keeps `doc`, `asText`, `reloads` on the disk tab; `diskReadOnly` includes `doc`. app.js `docShown` puts `DocumentView` over the editor's place (the host hidden; no language server, Git, model bubble or cursor for it); `actions.documentText` makes what the view read the tab's text (`store.diskPatch` + `host.replaceText`: search, Copy for Claude, the model), `documentAsText` toggles (DiskBar **As text** / **As it looks**; documents have no Follow or Save, their own ⋯ items, `actions.openOutside`), Reload bumps `reloads`. Bytes come from `disk:read-bytes` (main.cjs, 200 MB at most; preload `disk.readBytes`; androidApp.js reads content:// 8 MB at a time). `folders.js` `peekKind` 'doc', `opensHere` (text or document), `opensInEditor` is text only.
  - `documents.js` `convertDocument(kind, bytes)` → `{ html, text, title, toc, image(ref) }` with the pure converters in `docs/` (`docx.js` + its `relsOf`/`mainPart` for `xlsx.js`/`pptx.js`, `odf.js` for odt/ods/odp, `epub.js` with `cssLooks` (the book's CSS only for italic/bold/alignment classes), `fb2.js`, `rtf.js` (code pages, `\u`, fields, `\cellx` merges, pictures, footnotes), `common.js` (`esc`, `htmlToText`, `DocumentError`…)) over `xmlLite.js` (a forgiving XML parser: no DTDs or external entities) and `unzip.js` (central directory, zip64, `DecompressionStream('deflate-raw')` with a size limit per entry). The converters write only their own tags and attributes (pictures as `data-doc-img` refs, links only http(s)/mailto/tel or inside the page); `ui/documentView.js` sanitizes again with DOMPurify (`PURIFY`) and loads pictures as blob URLs. Tested on files from pandoc, LibreOffice, python-docx, openpyxl and python-pptx in `test/fixtures/documents/`.
  - PDFs: `pdfDoc.js` loads pdf.js (`vendor/pdf/`, the legacy build with its worker, wasm decoders, cmaps and standard fonts, `npm run vendor`; `files.json`, cached when first used) with `isEvalSupported: false`, scripting off; `openPdf` (`PdfPasswordNeeded`), `pdfOutline`, `pdfText`, `drawPage` (canvas capped at 12 MP, pdf.js's `TextLayer` to select). `PdfView`: placeholder pages sized from page 1, drawn by an IntersectionObserver around the screen (others let go), zoom by buttons, Ctrl+wheel and two fingers (keeping the point in place), Fit. Close a document with `pdf.loadingTask.destroy()` (`closePdf`: pdf.js 6 has no `destroy` on the document). Its `workerSrc` is `js/pdfWorker.js`, which imports `compat.js` (what older WebViews lack that pdf.js's legacy build does not bring: `ArrayBuffer#transferToFixedLength`, Chrome 114; `Promise.withResolvers`, Chrome 119; `for await` over a `ReadableStream`, Chrome 124; Chrome for Testing 113 from storage.googleapis.com reproduces them locally) and re-exports `pdf.worker.js` (also its fake worker on the page); `pdfDoc.js` imports `compat.js` too. The Android check runs an Android 14 emulator (WebView 113) for this.
  - Where a document is read (not `compact`): full screen (`ui/fullScreen.js` `useFullScreen(ref)`, shared with the preview pane: `.fills-screen`, fixed over the window at z-index 48 inside the safe areas, under dialogs, toasts and menus; `requestFullscreen` too except in the Android app, whose Capacitor declines it (`onShowCustomView`: the pane stayed under the status bar), where `desktop.android.bars(false)` hides the system bars; Escape (a window listener that skips handled ones) and Back leave it; the read-aloud bar shows inside it) and a bookmark (`bookmarkKey` = the path; `docBookmarks.js`, pure: settings `docBookmarks` by path, `MAX_BOOKMARKS`, `movedBookmarks` from `followDiskMoves`; a PDF's is `{ page, pages, into }`, a converted document's `{ block, into, heading, percent }` among `BOOKMARK_BLOCKS` (`placeAt`/`topOf`), so it holds on any width; `heading` from the contents' last entry before it). The view gives the bar `nav` (`here()`, `go(place)`); it opens at the bookmark and keeps that place (`anchor`) while pictures load and sizes settle, until the reader scrolls (`useHandScroll`) or 15 s pass.
  - Android: Open with for documents (an intent filter by MIME type in AndroidManifest.xml).
- Pasting files (desktop): the editor's paste handler gives files to `onPasteFiles` (`actions.openPastedFiles`: those with a path that are not pictures go to `disk.openPasted`; pictures stay with `onImage`), and a text that is a whole path (`pastedPath`) is pasted and offered by `onPastePath` (a toast with **Open** → `actions.openTypedPath`). A window `paste` listener does the same outside text fields (opening a path at once); the editor and the folders view take their pastes first (`defaultPrevented`).
- Saving:
  - Typing is saved 250 ms after the last key (editor debounce plus store debounce).
  - Pastes, drops and new tabs are saved at once: the editor passes `{ urgent }` and the store saves with ms 0.
  - `kv.js` writes with `durability: 'strict'` and `tx.commit()`.
  - `main.js` flushes pending saves on `pagehide` and when the app is hidden.
  - The Electron crash test kills the app 150 ms after a paste; keep it passing.
- `naming.js` (pure) names untitled tabs (`new N`) from their content: the model's reply via `cleanModelName`, or `nameFromHeading`. With the model it also files new notes: `filingMessages` asks for JSON `{ name, project, tags }`, `parseFiling` keeps only existing projects (their spelling) and at most 3 tags. `app.js` runs it a moment after text changes, once per new file, filling only empty fields, with Undo.
- History and compare: `versions.js` lists a file's versions from the commits API (`path` = the file's folder, which follows renames) and loads one. `editor.createCompareView` is `@codemirror/merge` (side by side, unified on phones); `ui/compare.js` takes the editor's place (sides `{ label, text, detail }`: `detail` says where the file is) for history, the model's replacements (`proposeReplacement`), Git's HEAD and a disk tab changed elsewhere; `ui/history.js` is the panel.

  - Files (`FileCompare`): `editor.createMergeEditor` (an editable `MergeView`; our `renderRevertControl` draws → and ← per chunk, copying as MergeView's revert does; `next`/`previous`/`copyHere`/`copyAll`/`text`/`setText`; Alt+↓/↑/→/← at `Prec.high`). `actions.readCompareSide` (an open tab's text, unsaved edits too; else `disk.read`, its format kept) and `saveCompareSide` (store first, then `host.replaceText`, which takes no part in the store; disk tabs through `saveDiskTab`, other files `disk.write` with `expectedMtime`/`expectedSize`). ## When changing things

- Adding or removing a file under `app/` → update `ASSETS` in `app/sw.js` (CodeMirror chunks are listed in `vendor/cm/files.json` instead, and text recognition in `vendor/ocr/files.json` and the terminal in `vendor/xterm/files.json`, both cached when first used). `test/app.test.js` enforces this.
- Bumping the version → update `package.json`, `app/js/version.js` and the `CACHE` name in `app/sw.js`. The tests check that they match. The Android app takes package.json's.
- Adding a module that `electron/main.cjs` imports from `app/js` (or one those import, like `folders.js` → `docTypes.js`) → add it to `PAGE_MODULES` in `scripts/android-node.js`; a package it needs → `PACKAGES`.
- The manifest `id` is `/tracker-editor/`. Ids resolve against the origin, and the tracker on the same origin (divaor.github.io) owns the origin root. Never change it: a new id makes installed copies a different app.
- The CSP in `app/index.html` allows only same-origin scripts. Fetches may go to any https origin and to `localhost` (the model and speech servers); `media-src` allows `blob:` for speech audio, `img-src` allows `blob:` for the folders view's pictures and documents' pictures. No `frame-src`: PDFs are drawn by pdf.js, not Chromium's viewer (the main window has no `plugins`).
  - Do not add inline scripts.
- Browser tests (Playwright) need `PLAYWRIGHT_DISABLE_FORCED_CHROMIUM_PROXIED_LOOPBACK=1` in this sandbox so `localhost` is not sent through the proxy. Electron tests need `xvfb-run`; typing into another window needs `xdotool` (`apt-get install xdotool`).
  - Server tests use OpenSSH's `sshd` (with `UsePAM yes` and `KbdInteractiveAuthentication yes` for the server's own password question), ssh2's `Server` for two-step sign-in (with `/usr/lib/openssh/sftp-server` behind its sftp subsystem; do not add an `sftp` listener), and pyftpdlib for FTP/FTPS.
  - Playwright's key presses do not reach Electron menu accelerators: click the menu item through `Menu.getApplicationMenu()` instead.
  - Without a keyring, `safeStorage` is unavailable under xvfb, so the clipboard history stays in memory there.
